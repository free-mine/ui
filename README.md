# Free Mine UI

Интерфейс фонда [Free Mine](https://github.com/free-mine) в Avalanche C-Chain:
портфель OreVein, балансы, покупка MagicOre и заявки на вывод.
Стек: React, TypeScript, Vite, SCSS и viem.

## Разработка

Нужны Node.js 24 версии не ниже 24.13.1 и npm.

```sh
npm ci
npm run dev
```

Публичный API предоставляет [free-mine/server](https://github.com/free-mine/server).
При разработке Vite проксирует `/v1` на `http://127.0.0.1:3000`.
Запуск сервера описан в `../server/README.md`.

Настройки из `.env.example` можно переопределить в `.env.local`:

| Переменная          | Назначение                | По умолчанию            |
| ------------------- | ------------------------- | ----------------------- |
| `VITE_API_BASE_URL` | Базовый URL API без `/v1` | Текущий origin          |
| `API_PROXY_TARGET`  | Адрес API для прокси Vite | `http://127.0.0.1:3000` |

## Сборка и размещение

```sh
npm run build
```

Содержимое `dist` размещается на статическом сервере с HTTPS. При пустом
`VITE_API_BASE_URL` настройте проксирование `/v1/*` на API. Для API на другом
origin задайте `VITE_API_BASE_URL` перед сборкой и разрешите CORS на сервере API.
Изменение этой переменной требует пересборки; `API_PROXY_TARGET` действует
только при разработке.

`npm run preview` запускает готовую сборку локально. Навигация использует
URL-фрагменты, поэтому fallback для SPA-маршрутов не требуется.
Шрифты и их лицензии находятся в `public/fonts`.

## Данные и операции

UI читает `GET /v1/state`, `GET /v1/status` и `GET /v1/backup`. Снимок и статус
опрашиваются каждые 30 секунд в видимой вкладке. Обновление в UI перечитывает API,
а синхронизацией с блокчейном управляет сервер. При ошибке последний доступный
снимок сохраняется с предупреждением и датой.

Кошельки обнаруживаются через EIP-6963 и `window.ethereum`. Балансы и транзакции
используют RPC выбранного кошелька; операции разрешены только в Avalanche
C-Chain (43114). Отключение в UI завершает локальную сессию, но не отзывает
разрешения сайта в расширении.

Особенности контрактов, которые нужно учитывать при изменении UI:

- `buy` не принимает `minOut`: повторная проверка цены перед подписью не защищает
  от её изменения до исполнения. Разрешение ERC-20 выдаётся на точную сумму;
  недостаточное ненулевое разрешение сначала сбрасывается в ноль.
- Суммы рассчитываются через `bigint`. Лишние десятичные знаки при вводе
  отклоняются, а точное значение отображаемой суммы доступно в подсказке.
- Заявка требует больше 1 MagicOre без ERC-20 approve. Отмена удерживает
  1 MagicOre. Выплата использует долларовый токен и масштаб профинансированной
  смены, которые могут отличаться от текущих.
- После прерванного ожидания транзакции «Проверить статус» запрашивает её receipt
  без повторной отправки. До выяснения результата новые операции блокируются.
- В Uniswap `storedOwed` и `totalCollectable` могут включать выведенный капитал;
  только `newlyAccruedFees` обозначает новые комиссии.

## Проверки

```sh
npm run check
npx playwright install chromium
npm run test:e2e
```

`check` объединяет линтеры, Prettier, модульные тесты, TypeScript и сборку.
Playwright использует подменённые ответы API и кошелька; сервер и реальные
транзакции не нужны. Эти же проверки выполняются в CI на Pull Request.

Вместо установки Chromium можно использовать установленный Chrome, задав
`PLAYWRIGHT_CHANNEL=chrome`. В PowerShell:

```powershell
$env:PLAYWRIGHT_CHANNEL = 'chrome'
npm run test:e2e
```
