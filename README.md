# Free Mine UI

Интерфейс для работы пользователей с организацией https://github.com/free-mine. Представляет собой собираемый фронтенд, для дальнейшей публикации директории `dist` на сервере.

## Работа с сервером

Интерфейс взаимодействует с сервером из репозитория https://github.com/free-mine/server. Локально этот репозиторий находится в соседней директории, так что можно запускать его в Docker для помощи в разработке.

## Работа с блокчейном

Некоторые операции (например, покупка `MagicOre`) требуют подписания транзакции от имени пользователя. Соответственно, необходима интеграция с браузерными кошельками, такими как MetaMask, Rabby и т.д. Работа с ними должна быть удобной. Вся работа происходит строго в сети Avalanche C-Chain.

## Функциональность

Интерфейс позволяет видеть свой баланс токена `MagicOre`, текущего доллара `FreeMine`, покупать `MagicOre` за доллар, а также управлять заявками на вывод.

В интерфейсе можно наблюдать за размещением капитала в контракте `OreVein`. Каждая торговая пара должна иметь ссылку на Uniswap, позволяющую рассмотреть эту торговую пару в интерфейсе Uniswap. Для ознакомление с портфелем Фонда целиком в независимом источнике интерфейс предоставляет ссылку на DeBank.

Все публичные агрегированные данные от сервера должны иметь отражение в интерфейсе.

## Дизайн

Создай уникальный брендовый дизайн для UI инвестиционного Фонда. Не ставь точку после текста заголовка любого уровня. Не добавляй бессмысленных мотивационных фраз. Интерфейс должен быть удобным, не перегруженным и привлекательным.

## Запуск интерфейса

Реализация использует React, TypeScript, Vite, SCSS и viem. Нужен Node.js 24
версии не ниже 24.13.1 и npm. Все зависимости закреплены в `package-lock.json`.

```sh
npm ci
npm run dev
```

Откройте адрес из вывода Vite. В режиме разработки запросы `/v1` проксируются
на `http://127.0.0.1:3000` — публичный сервер из соседнего репозитория `../server`.
Для его запуска следуйте его README. Docker-файлов в UI нет.

Необязательные настройки можно скопировать из `.env.example` в `.env.local`:

| Переменная          | Назначение                                    | По умолчанию            |
| ------------------- | --------------------------------------------- | ----------------------- |
| `VITE_API_BASE_URL` | Базовый URL публичного API, без `/v1` в конце | Текущий origin          |
| `API_PROXY_TARGET`  | Адрес сервера для прокси Vite при разработке  | `http://127.0.0.1:3000` |

Например, `VITE_API_BASE_URL=https://api.example.org` отправляет запросы на
`https://api.example.org/v1/state`. Переменные `VITE_*` встраиваются в браузерную
сборку: после изменения нужна новая сборка. Секреты и ключи владельца UI не нужны.

## Сборка и размещение

```sh
npm run build
```

Готовый сайт находится в `dist`. Разместите содержимое каталога на статическом
сервере с HTTPS. При пустом `VITE_API_BASE_URL` сервер должен проксировать
`/v1/*` на публичный API. Если API расположен на другом origin, задайте его
адрес перед сборкой; API должен разрешать CORS. `API_PROXY_TARGET` действует
только в dev-режиме и не настраивает production-сервер.

Навигация использует URL-фрагменты (`#overview`, `#account`, `#portfolio`,
`#data`), поэтому специальный fallback для SPA-маршрутов не требуется.
`npm run preview` позволяет проверить готовую сборку локально; для API укажите
`VITE_API_BASE_URL` перед сборкой или используйте свой reverse proxy.
Шрифты размещены локально, лицензии лежат в `public/fonts`.

## Данные и операции

- **Обзор фонда**: цена входа, выпуск MagicOre, токены в заявках, держатели,
  состояние Aave, балансы OreVein и торговые пары.
- **Мой кошелёк**: текущие балансы MagicOre, долларового токена FreeMine и AVAX,
  покупка, создание, отмена и получение заявок на вывод.
- **Размещение капитала**: свободные средства, вклады и долги Aave, Health
  Factor, все пулы и NFT-позиции Uniswap, диапазоны и начисления.
- **Данные фонда**: адреса контрактов и владельцев, администраторы, преемники,
  держатели, смены и все активные заявки, статус сервера и скачивание gzip-снимка.

UI читает только публичные `GET /v1/state`, `GET /v1/status`, `GET /v1/backup`.
Опрос выполняется каждые 30 секунд в видимой вкладке. Кнопка обновления заново
читает API, не запускает защищённую синхронизацию сервера. При недоступности API
или ошибке синхронизации последний успешный снимок остаётся видимым с его датой.
До первого успешного ответа показывается состояние загрузки или ошибка без
подставных балансов. Сервер не отдаёт историю доходности или оценку NAV: UI их
не придумывает и не складывает разные токены как одну валюту.

Кошельки обнаруживаются по [EIP-6963](https://eips.ethereum.org/EIPS/eip-6963),
с поддержкой `window.ethereum` для старых провайдеров. Подключение инициирует
пользователь. Все операции проверяют аккаунт и
[Avalanche C-Chain, chain ID 43114](https://build.avax.network/docs/primary-network).
Чтение баланса и отправка операций используют RPC выбранного кошелька.
Отключение в UI завершает локальную сессию; разрешения сайта в расширении
кошелька пользователь может отозвать отдельно.

Покупка сначала проверяет текущие цену и доллар в контракте, затем при
необходимости запрашивает ERC-20 allowance на точную сумму и ожидает подтверждения.
При ненулевом недостаточном allowance сначала выполняется сброс в ноль.
Перед покупкой цена проверяется повторно. Сам контракт `buy` не принимает
`minOut`, поэтому изменение цены между подписью и исполнением предотвратить
на стороне UI невозможно. Суммы вычисляются через `bigint`, ввод с лишними
десятичными знаками отклоняется. Отображение сокращает дробную часть; точное
значение доступно в подсказке у суммы.

Если транзакция отправлена, но ожидание подтверждения прервалось, новые операции
в текущем сеансе приостанавливаются. Кнопка «Проверить статус» запрашивает receipt
без повторной отправки. После подтверждения обновляются балансы и заявки;
подтверждённое разрешение на расход отдельно обозначается как разрешение,
после которого покупка ещё не отправлена.

Заявка требует больше 1 MagicOre и не требует ERC-20 approve. Отмена сжигает
1 MagicOre — перед подписью UI явно показывает удержание и возвращаемую сумму.
Выплата доступна после финансирования смены и использует именно доллар и масштаб
этой смены. Через 14 дней после финансирования владелец может закрыть
невостребованную заявку с тем же удержанием. Новая подтверждённая заявка появляется
сразу по событию транзакции; публичные реестры обновляются по расписанию сервера.

В Uniswap `newlyAccruedFees` отображаются как новые комиссии, а `storedOwed` и
`totalCollectable` как суммы к получению, поскольку они могут включать выведенный
капитал. Каждая существующая торговая пара открывает свой пул в Uniswap;
ссылка DeBank ведёт на адрес OreVein.

## Проверки и CI

```sh
npm run check
npx playwright install chromium
npm run test:e2e
```

`check` запускает ESLint и Stylelint с нулевым допуском предупреждений,
Prettier, модульные тесты, проверку TypeScript и production-сборку.
Playwright проверяет браузерные сценарии на контролируемых ответах API и
кошелька, без реальных переводов. Тестовые данные находятся только в `tests`
и не попадают в пользовательскую сборку.

Если Chrome уже установлен, локально можно запустить тесты с
`PLAYWRIGHT_CHANNEL=chrome` (в PowerShell:
`$env:PLAYWRIGHT_CHANNEL='chrome'; npm run test:e2e`).

Workflow `.github/workflows/pull-request.yml` выполняет все проверки и Chromium-тесты
на каждом Pull Request. GitHub Actions закреплены по SHA;
Dependabot проверяет обновления npm и Actions. Для CI не нужны API, RPC или
секреты. TypeScript и Stylelint выбраны в последних стабильных версиях,
совместимых с установленным Node.js 24.13.1 и typescript-eslint.
